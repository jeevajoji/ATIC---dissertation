ATIC RESEARCH AND IMPLEMENTATION PHASE PLAN
===========================================

Primary research direction
--------------------------

Decoder-Synchronised Attention Distillation (DSAD), followed by the more
ambitious Value-of-a-Bit / Marginal-Utility allocation extension.

The final codec must be valid: the decoder may use only the compressed file,
the installed decoder weights, and metadata stored in the file. It must never
need the original image or private encoder features.


CURRENT EXECUTION GATE
----------------------

The DSAD wiring pilot, frozen sequence-disjoint UVG bundle, beta calibration,
and three-seed beta=8 confirmation are complete. The independent Beauty test
sequence remains locked. At lambda_rd=0.0067, DSAD improved validation PSNR
and LPIPS in all three confirmation seeds, but increased actual BPP in all
three. These single-rate results therefore do not prove better compression.

The four-rate extension exposed a more fundamental blocker: both the
Full_ATIC_NoDSAD control and DSAD curves were non-monotonic for all three
seeds, so zero of three seeds produced a valid PSNR BD-rate curve. Because
the matched control also failed, this is a baseline training/rate-control
failure rather than evidence for or against DSAD.

The first baseline-rescue run used:

1. deterministic cosine learning-rate decay;
2. a substantially longer training budget;
3. validation-RD checkpoint selection instead of the final epoch;
4. checkpoint eligibility only after the DSAD warm-up/ramp in paired runs;
5. a control-only four-rate, one-seed monotonicity gate.

It removed the earlier catastrophic PSNR collapses, but still failed because
actual BPP and PSNR were non-monotonic. Estimated and actual rate had the same
ordering, and header BPP was constant, so entropy-coder/container accounting
did not cause the reversal.

Do not unlock Beauty, calculate publication BD-rate, tune DSAD further, or
claim compression novelty until a control produces a monotonic validation RD
curve. Under the subsequently identified clipping confounder, disabling
adaptive gain with No_AdaptiveQuant failed, including a severe low-lambda
collapse. This observation cannot now isolate adaptive gain causally. Replacing
SAG BatchNorm with GroupNorm also failed, but the later audit showed that
GroupNorm(1, 1) imposed a strong one-channel spatial normalisation before every
SAG sigmoid, so that intervention did not cleanly isolate BatchNorm either.

The code audit found a definite optimiser-boundary defect: stale auxiliary
entropy-quantile gradients were included in the following batch's global
model-gradient clipping norm. The correction clears auxiliary gradients before
the main backward pass, clips only main-optimiser parameters, clears auxiliary
gradients after their update, and logs main/auxiliary gradient norms plus the
main clipping fraction. All earlier long runs share this confounder.

Do not use the archived Baseline for the trainer sanity gate because disabling
overlap changes the 512x512 latent geometry from 8x8 to 4x4. Use the new
Plain_Swin_Hyperprior variant: overlap and hyperprior remain enabled; SAG,
CBAM, and adaptive gain are disabled.

The corrected two-rate Plain_Swin_Hyperprior diagnostic is complete. The
high-lambda arm increased estimated BPP by 0.014384 and actual complete-file
BPP by 0.014160, so both numeric rate checks passed. PSNR increased by only
0.150 dB, below the predeclared 0.250 dB margin, so the numeric criterion
failed. The selected checkpoints occurred at epochs 8 and 3 and achieved only
10.023 and 10.174 dB, respectively.
These runs were also marked Git-dirty solely because six pre-existing,
untracked root-level log files were visible to the provenance recorder.
Their metrics are retained as diagnostic-only evidence and are not eligible
for a publication claim.

DSAD and the four-rate ATIC curve remain stopped. The next predeclared check
is an official pretrained CompressAI MeanScaleHyperprior oracle evaluated
with real bitstreams on the same frozen validation split. This tests whether
the dataset/evaluation pipeline can exhibit the expected rate-quality response
without consuming another long training budget. If the oracle passes, first
isolate the encoder terminal latent LayerNorm while holding the current data
fixed; training-data expansion is a subsequent, separately controlled change.
Beauty remains locked.

The oracle protocol is fixed before execution:

1. official CompressAI 1.2.8 mbt2018_mean MSE checkpoints;
2. pretrained quality levels 1 and 8;
3. the 60-image ShakeNDry validation manifest only;
4. rate from the real y+z entropy-string payload returned by compress();
5. quality from the reconstruction returned by decompress();
6. a clean Git commit and the pinned Torch/CUDA/dependency environment; and
7. minimum quality-8 minus quality-1 margins of 0.01 BPP and 0.25 dB PSNR.

This oracle uses payload BPP because the upstream reference has no ATIC
container header. It tests pipeline response and is not a direct absolute-BPP
comparison against the complete .atic file rate.

The oracle passed:

    quality 1: 0.073659 payload BPP, 31.061 dB
    quality 8: 0.891030 payload BPP, 41.072 dB
    delta:     +0.817371 BPP, +10.011 dB

All ordering and margin checks passed, and Beauty remained locked. This
supports the dataset/evaluation pipeline being capable of a healthy response;
it does not by itself prove which ATIC component is responsible.

The next isolated ATIC diagnostic trains both arms fresh:

    control:       Plain_Swin_Hyperprior
    intervention:  Plain_Swin_Hyperprior_NoLatentNorm

The intervention replaces only the encoder's terminal, 1024-channel
LayerNorm immediately before entropy coding with Identity. It does not alter
tokenizer, PatchMerging, decoder, reconstructor, entropy-model, latent-grid,
optimizer, data, or checkpoint-selection settings. Removing the norm also
removes its 2,048 affine parameters, so this is an architecture/rate-control
diagnostic rather than a DSAD claim.

Both variants use seed 42, lambdas 0.0018 and 0.013, 60 epochs, batch size 4,
the corrected optimiser, cosine learning rates, DSAD beta 0, and locked
validation-only bitstreams. The no-norm diagnosis passes only if:

1. its high-minus-low actual BPP is at least +0.01;
2. its high-minus-low estimated BPP is positive;
3. its high-minus-low PSNR is at least +0.25 dB; and
4. its post-hoc actual-rate RD score,
       BPP_actual + lambda * 255^2 * MSE,
   is strictly lower than the freshly trained control at both lambdas.

The archived dirty Plain checkpoints are not used as the control.
The gate also requires matching paired-common initial-state hashes computed
after excluding only encoder.norm.weight and encoder.norm.bias.
Checkpoint selection still uses estimated validation RD; the score in item 4
is a post-hoc comparison, not the optimized checkpoint-selection objective.

The terminal-latent-norm diagnostic completed with the following
high-minus-low responses:

    control:  actual BPP +0.014160, PSNR +0.151 dB
    no norm:  actual BPP +0.120119, PSNR +1.685 dB

The no-norm arm passed the rate-response sub-gate, while the control did not.
The overall gate failed because no norm was +0.024536 worse by the post-hoc
actual-rate RD score at lambda 0.0018. It was -24.895472 better at lambda
0.013. This is a partial rate-control rescue, not proof of uniform compression
superiority. Beauty remains locked. The next action is a read-only audit of
the recorded latent amplitude, residual-zero, predicted-scale, convergence,
and selected-checkpoint diagnostics before any new training is selected.

That audit found a transient useful entropy regime only in the selected
high-rate no-norm checkpoint: 3.25% of raw predicted scales were below 0.11
and 80.81% of residual symbols were zero. By epoch 60 these values became
99.96% and 100%, respectively, and validation RD degraded by 32.205363.
Every high-rate batch was gradient-clipped. Because CompressAI internally
lower-bounds scales at 0.11, this is not a coder-validity defect. Before
changing the entropy scale head or optimiser, compare training and validation
trajectories to distinguish overfitting from collapse on both splits.

The trajectory comparison found both:

1. control-low, control-high, and no-norm-low improved training RD while
   validation RD worsened, establishing sequence/domain overfitting; and
2. no-norm-high worsened by +0.3346 training RD and +32.2054 validation RD,
   establishing optimisation/entropy collapse on both splits.

All final training MSE values converged near 0.05048 independently of lambda.
The next ordered actions are therefore:

1. a high-rate no-norm gradient-clipping calibration on the current frozen
   training/validation protocol; then
2. a new, larger and content-diverse sequence-disjoint training corpus after
   optimizer stability is established.

Do not resume multi-rate DSAD training or unlock Beauty before both gates pass.

PHASE 1 - ESTABLISH A TRUSTWORTHY BASELINE
------------------------------------------

Actions:

1. Freeze the current code and results in version control.
2. Select one clean baseline containing the encoder, hyperprior, entropy
   model, and decoder.
3. Remove or isolate inactive components from the experimental path.
4. Create leakage-free training, validation, and independent test splits.
5. Train at least six rate points instead of only three.

Reason:

This makes it possible to prove that an improvement is caused by the new
method instead of data leakage, configuration differences, or broken rate
control.

Exit condition:

The baseline is reproducible and produces monotonic rate-distortion curves on
an independent test set.


PHASE 2 - BUILD A REAL CODEC
----------------------------

Required interface:

    compressed_file = model.compress(image)
    reconstructed_image = model.decompress(compressed_file)

The compressed ATIC file should contain:

    Header
    z_bytes
    y_bytes

Encoding order:

    image -> y -> z -> quantise z -> entropy-code z_bytes
                              |
                              +-> hyperdecoder -> parameters for y
                                                   |
                              quantise and entropy-code y_bytes

Decoding order:

    z_bytes -> z_hat -> hyperdecoder
                           |
                           +-> decode y_bytes -> y_hat
                                                   |
                                                   +-> decoder -> image

Use an actual entropy coder, such as rANS through CompressAI, instead of
storing tensors in NPZ files.

Actual bitrate:

    actual_bpp = (8 * compressed_file_size_bytes) / (width * height)

Required tests:

1. decompress(compress(image)) works in a fresh process.
2. The decoder never accesses the original image.
3. The reconstructed image matches the evaluation forward pass.
4. Estimated BPP is close to actual BPP.
5. Different image dimensions decode correctly.
6. A saved file still decodes after restarting the program.

Exit condition:

One .atic file can be transferred to a different computer that has the
matching decoder, and that computer can reconstruct the image.


PHASE 3 - ADD A DECODER-SYNCHRONISED GAIN MAP
----------------------------------------------

Add a small student gain head to the hyperdecoder:

    z_hat
       |
    hyperdecoder features
       +-> probability parameters: mean and scale
       +-> student gain head -> spatial gain map

The gain map may depend only on:

1. z_hat;
2. installed decoder weights; and
3. settings stored in the compressed-file header.

It must not depend on the original image, unavailable encoder features, or
values of y that have not yet been decoded.

Both encoder and decoder must execute the same operation:

    student_map = gain_head(hyperdecoder(z_hat))

Possible gain formulation:

    k = round(y * g)
    y_hat = k / g

where g > 1 gives finer quantisation and g < 1 gives coarser quantisation.
The entropy-model parameters must be transformed consistently:

    mean_k = mean_y * g
    scale_k = scale_y * g

Important invariant:

The deployable encoder and decoder both use the student map. The encoder-only
teacher map is never used to construct a final bitstream.

Exit condition:

Hashes or exact comparisons prove that the encoder and decoder generate the
same gain map from the same decoded z_hat.


PHASE 4 - INTRODUCE THE TRAINING-ONLY TEACHER
----------------------------------------------

The existing encoder attention/SAG component becomes the teacher:

    encoder features -> teacher attention map
    z_hat            -> student attention map

Initial objective:

    total_loss = R_y + R_z + lambda * distortion
                 + beta * distillation_loss

Initial distillation loss:

    distillation_loss =
        L1(student_map, stop_gradient(teacher_map))

Training sequence:

1. Train the ordinary codec.
2. Train or stabilise the encoder-side teacher.
3. Freeze or detach the teacher.
4. Train the student to reproduce the teacher map.
5. Fine-tune the complete codec while using the student map.
6. Remove the teacher from compress() and decompress().

The teacher is training equipment only. It is not included in the compressed
file and is not required by the receiver.

The current direct implementation uses an online stop-gradient teacher: the
SAG teacher evolves through the ordinary rate-distortion objective, but the
DSAD term cannot update it through the target branch. A separately pretrained
and fully frozen teacher remains a later ablation, not a current claim.

Exit condition:

The student predicts the teacher map accurately enough to improve real
rate-distortion performance, not merely map-similarity loss.


PHASE 5 - PREVENT THE GAIN MAP FROM CHEATING
---------------------------------------------

Use a bounded positive gain, for example:

    log_g = a * tanh(student_output)

Normalise its geometric mean so that it mainly reallocates bits spatially:

    g_normalised = g / exp(mean(log(g)))

Record:

1. total BPP;
2. y BPP;
3. z BPP;
4. average, minimum, and maximum gain;
5. teacher-student map similarity; and
6. payload-versus-estimated BPP calibration error; and
7. complete-file-versus-estimated BPP gap, reported separately so the fixed
   header is not mistaken for entropy-model error.

Reason:

Geometric-mean-one gain removes global scale as an easy shortcut, but it is
not an equal-bitrate constraint. The method should move coding emphasis from
low-value regions to high-value regions, and every claimed rate effect must be
verified from actual y, z, and header bytes. It must not appear successful
merely by increasing every gain value or hiding an expensive map inside z.


PHASE 6 - RUN THE ESSENTIAL ABLATIONS
--------------------------------------

Train all versions with identical data, seeds, lambda values, epochs, and
evaluation settings:

1. Plain hyperprior baseline.
2. Student gain without teacher distillation.
3. Student gain with distillation (proposed DSAD).
4. Explicitly transmitted attention map.
5. Teacher/oracle map as a non-deployable upper bound.
6. Uniform-gain control.

Required conclusion:

DSAD succeeds only if it beats both the plain hyperprior and the
student-without-distillation model after counting every y bit, z bit, header
bit, and any explicit side-information bit.


PHASE 7 - PUBLICATION-QUALITY EVALUATION
-----------------------------------------

Datasets:

1. Kodak.
2. Tecnick.
3. CLIC validation/test data where permitted.
4. HoneyBee or another independent, texture-heavy dataset.

Report:

1. Actual BPP from the compressed file.
2. PSNR and BD-rate.
3. MS-SSIM.
4. LPIPS or DISTS.
5. Edge and fine-texture preservation.
6. Encoding and decoding time.
7. Parameter count.
8. z bitrate as a percentage of total bitrate.
9. At least three random seeds.
10. Strict deterministic-algorithm enforcement, with any unsupported CUDA
    operation treated as an error rather than a warning.

Use at least six rate points and matched actual bitrates for every comparison.

Initial paper-success target:

1. A consistent rate-distortion improvement over the identical backbone; or
2. significantly better texture/perceptual quality at matched actual BPP;
3. no separately transmitted attention map;
4. small runtime overhead; and
5. an ablation proving that distillation caused the improvement.

A consistent 2-5 percent BD-rate improvement over a strong, identical
backbone would be meaningful if supported by rigorous experiments. Global
SOTA is not required for the first paper claim.


PHASE 8 - VALUE-OF-A-BIT / MARGINAL-UTILITY EXTENSION
------------------------------------------------------

Only begin this phase after the basic DSAD codec works.

For each latent region:

1. Reconstruct it using ordinary quantisation.
2. Give only that region slightly finer quantisation.
3. Measure the additional bits.
4. Measure the quality improvement.
5. Calculate its marginal utility:

       utility_i = quality_improvement_i / additional_bits_i

The encoder-side teacher estimates these utilities during training. The
student predicts them using only z_hat. A differentiable allocator then gives
the limited bit budget to the regions with the greatest predicted utility.

Ambitious contribution:

    Decoder-synchronised allocation based on the predicted marginal value of
    each additional bit.
